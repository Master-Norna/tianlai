# 渲染输出目录

`output/` 保存渲染结果、候选回执、机器报告和可删除缓存。除本说明外，目录内容
默认不进入 Git，也不属于轻量源码发布包。

## 常用位置

| 路径 | 用途 |
| --- | --- |
| `作品/<曲名>/<版本>/` | 经创作者确认保留的合奏、分轨、计划、回执与许可旁车 |
| `mcp/<作品 ID>/<候选 ID>/` | MCP `render` 生成的不可变候选 |
| `mcp-workspaces/<会话或曲名>/` | 尚未确认的 score、roster、补丁结果和客户端状态 |
| `诊断/` | 一次性环境检查、协议检查与问题定位材料 |
| `.tianlai-cache/stems/` | 用于加速重渲染的原始分轨缓存 |

其他试音、全音域扫描或 A/B 目录也属于按需生成内容，不应当作为源码或唯一创作
源保存。

## 候选与作品

CLI `project-render` 默认写入 `output/候选/`，MCP `render` 写入 `output/mcp/`。
候选目录由 `候选.json` 和渲染回执绑定，应按不可变快照使用。确认收录后，使用
同一份 score、roster 和可选 space 复制或重新渲染到
`作品/<曲名>/<版本>/`；不要移动或覆盖原候选来冒充新结果。

一个可复现的作品版本至少应保留：

- score、roster，以及使用过的 space 或渲染参数；
- 合奏和所需分轨；
- `渲染回执.json`；
- `许可与署名.json/.txt`。

只有 WAV、没有可复现输入和回执的目录，不是完整项目归档。

## 工作区与缓存

Agent 或客户端可把未确认材料写入 `mcp-workspaces/`。创作者确认后，再把可编辑
源移入 `乐谱/曲目/`，把成品写入 `作品/`。`tools/`、`docs/` 和产品源码目录不
应当用作会话草稿区。

渲染进行时，不要移动或清理正在使用的候选目录、`.tianlai-cache/`、
`.candidate-*.render-stage.*` 或 `.tianlai-render-*.lock`。等待进程结束并确认
回执完整后再整理。

`.tianlai-cache/` 可以整目录删除；删除不会损坏乐谱或作品，只会让下次渲染
重新计算分轨。缓存不是正式资产，也不能替代已与音频绑定的许可旁车。

## 权利与备份

原创作品、唯一的人工导出和尚未另存 score 的结果不可按临时文件处理。清理输出
前，先保存创作源、score、roster、space 和必要回执，并按自己的备份策略归档。

Apache-2.0 代码许可不会自动附着到输入作品或音乐输出，第三方音源继续受各自
许可证约束。公开音频前请检查随本次渲染生成的许可旁车，并阅读
[`OUTPUT_RIGHTS.md`](../OUTPUT_RIGHTS.md)。
