# 编钟（程序建模）

这是第 103 件乐器的第一版程序建模后端。它不需要下载音源，使用确定性的
非谐模态银行逐帧合成钟体响应，当前音域为 C2–D7（MIDI 36–98）。

可用奏法：

- `zhenggu`：正鼓／正面击，默认；主音更厚，较高模态较集中。
- `cegu`：侧鼓／侧面击；使用另一套代表性模态比例，谱重心与余韵不同且
  更紧凑（不预设它在所有音区都一定更亮）。

这里有一个重要的乐谱语义：两个奏法收到相同 MIDI note 时，最终主音
相同。真实双音钟在同一枚钟的不同击位通常会给出两个不同音高；为了让
AI 和乐谱不用猜隐藏移调，本引擎把奏法理解成“从一套假想钟中选择能够
发出目标音高的正鼓钟或侧鼓钟”。因此它是适合创作工具的声音模型，不是
同一枚实物钟的逐击位复原。

`expression` 控制整体动态，`modulation` 平滑改变高模态比重。力度同时
控制响度、击槌瞬态与高模态亮度。所有音都是自然衰减的 one-shot；
`note_off` 只释放事件 ID，不会截断钟声。

当前状态是 `formal / untested`：程序级音准、确定性、带限、复音余量及
人工单音色试听已经通过；`formal` 只表示独奏入口验收，不表示已经完成
真实曲目中的协奏与混音核验。

当前人工复核可运行：

```powershell
& .venv\Scripts\python.exe 乐器\世界乐器\编钟\核验试听.py
```

它会生成两份临时音频：

- `01_编钟_正鼓全音域上行.wav`：C2–D7 每个半音一次，检查音域连续性、
  后段攻击是否变轻以及长尾密集时是否失真。
- `02_编钟_正鼓与侧鼓对照.wav`：低、中、高音区各按“正鼓、侧鼓”顺序
  成对播放；每段使用独立引擎实例，便于判断两种击位是否仍像同类钟。

已知限制：

- 没有使用任何特定历史编钟的逐钟尺寸、合金、悬挂与实测脉冲响应。
- 没有合成房间长混响；听到的尾音来自钟体模态自身的自然衰减。
- 音域是创作工具的代表性覆盖，不等于某一套实物编钟的逐钟音域表。
- 目前只有一个确定性模型版本，没有真实槌型、距离或麦克风多层采样。
