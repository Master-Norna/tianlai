# 乐器索引

乐器按“乐器家族 → 声部组 → 具体乐器”组织。当前有 **103 个登记声音入口**、
1 个测试工具。103 个入口都已有可加载的专用实现，没有任何一个靠通用
SoundFont 出声；当前绑定版本均已通过单乐器/单音色独立试听，因此都标记为
`quality_tier=formal`。

## 双轴状态

- **单音色正式层（103，全部）**：`quality_tier=formal` 只表示当前绑定版本通过
  单乐器/单音色独立试听。每个入口都有自己的采样映射、物理/信号建模或确定性
  DSP，并带资源冻结、音准校准或不适用声明、固定试听核验与复算脚本。103 个
  入口使用同一套质量状态，不按加入时间划分高低等级。
- **协奏待测（103，全部）**：`collaboration_review_status=untested` 表示尚未
  通过多乐器协作、编配、混音与实际曲目验收。
- **测试工具（1）**：参考振荡器只验证音准、调度和确定性，不模拟声学乐器，
  因此不计入 103。

`formal` 不代表全部奏法、力度层、Round Robin、严格高质量音域或专家身份已经
覆盖，也不代表许可、公开发布、trusted 默认策展或合奏已经通过。许可状态和
`可信乐器.json` 与质量级别独立。当前第三方资源为 43 个 `approved`、31 个
`grandfathered`、0 个 `quarantined`。`grandfathered` 只允许按冻结许可与官方
安装边界使用，不能解释为取得原始采样再分发权。

在项目根目录运行 `python -m tianlai progress`，可查看 98 项扩展注册表的机器
可读状态；它不是 103 个声音入口的总数。总体能力边界见
[`docs/当前状态.md`](../docs/当前状态.md)。

## 每件入口的统一工件

103 个目录一律包含：

- `乐器.json`：类型、质量级别、显式回退策略与参数；
- `资源核验.json` + `核验资源.py`：逐文件 SHA-256 与许可证据，或自研引擎的源文件哈希；
- `音准校准.json` + `校准音准.py`：实测音准诊断，或写明理由的“不适用”声明；
- `试听核验.json` + `核验试听.py`：固定谱例渲染的峰值/RMS/削波/WAV 哈希；
- `README.md` 与 `来源.md`：实现说明、来源许可与已知限制。

## `formal` 的准确边界

单件入口只有在当前绑定实现、资源与独立试听材料一致，且单乐器/单音色试听通过
后，才可标记为 `quality_tier=formal`。它是基础乐器层的可用性结论，不是项目
所有质量问题的总开关。

更细的奏法 × 音高 × 力度 × RR/运行变体矩阵继续由 `range_profiles` 与
`strict_hq` 单独门禁；专家身份、许可与公开发布也各自保留独立结论。多乐器作品
只有经过协作、编配、声部平衡、混音和实际曲目听审后，才可把对应入口或作品的
`collaboration_review_status` 从 `untested` 推进。当前 103 件在单音色轴均为
`formal`，协奏轴均为 `untested`；详情以
[`docs/当前状态.md`](../docs/当前状态.md) 为准。

## 目录约定

- 每件乐器的清单、行为代码、校准结果、来源和说明放在自己的中文目录中。
- 多件同族乐器可以共享公共后端，但不能用相同采样或同一 GM 鼓键冒充不同乐器。
- 所有大型采样、上游音源库、原生运行库和下载缓存统一放在根目录 `音源/`。
- 103 个入口都声明 `fallback_policy: explicit_only_no_silent_gm`：资源缺失时明确报错，绝不静默降级成通用 SoundFont 冒充专用音色。

GeneralUser GS 与 TimGM 只供用户显式进行本机兼容或后端测试，不参与默认、
public/trusted、MCP 或协作层路由；任何一个加载失败都不会自动换用另一个。

现有实现可分别作为力度与踏板、弓弦奏法、独立释音和木管连奏的参考，但新乐器必须根据自身采样与演奏机制重新设计，不能只替换名称。
