# Windows 安装与巡检

Windows 10/11 x64 与 Windows PowerShell 5.1 是完整参考环境。天籁使用项目自己的
虚拟环境，不要求把 FluidSynth 或 Python 依赖安装到系统目录。Linux / WSL 用户
请参阅 [Linux / WSL 快速开始](Linux快速开始.md)；Mac 用户请参阅
[macOS 快速开始](macOS快速开始.md)。

## 准备 Python

需要 64 位 CPython 3.11–3.14。没有 Python 时，可从
[Python 官方 Windows 下载页](https://www.python.org/downloads/windows/)
安装 64 位版本，并确保 `py.exe` 或 `python.exe` 可从命令行调用。

不受支持的实现、版本或 32 位解释器会在创建环境前被拒绝，不会留下可误用的
半成品 `.venv`。

## 安装最小运行环境

在源码包根目录运行：

```cmd
安装运行环境.cmd
```

该入口会：

1. 创建或复用项目内的 `.venv`；
2. 安装核心与 MCP 依赖；
3. 运行环境诊断；
4. 用参考振荡器生成 `output\首次出声\参考振荡器.wav`。

参考振荡器不依赖第三方采样，因此无需先下载数 GB 音源。只安装和检查、不生成
WAV 时使用：

```cmd
安装运行环境.cmd -SkipSmoke
```

安装脚本不会修改系统的持久 PowerShell 执行策略。

## 查看当前状态

```cmd
检查运行环境.cmd
```

报告会分别显示代码与目录是否可用，以及每件外部资源是 `ready`、`missing` 还是
`invalid`。缺少尚未安装的完整资源是正常状态；已经出现但不完整、摘要不符或
许可证据缺失的资源会明确报告为异常。

需要简短报告时：

```cmd
检查运行环境.cmd --quick
```

资源状态始终以本机当次检查为准。源码包不包含大型第三方采样。

## 按需恢复外部音源

项目共有 103 件正式声音入口：29 件项目自研 DSP、合成或拟音入口不需要第三方
音频资产，另外 74 件依赖外部公开资源。先只读查看许可、下载量、磁盘空间和本机
状态：

```cmd
安装可恢复音源.cmd -PlanOnly
```

确认后运行：

```cmd
安装可恢复音源.cmd
```

脚本会显示完整计划，并要求输入精确的 `INSTALL` 后才开始下载和安装。全部 74 件
外部资源都由统一恢复清单覆盖，共 15 个资源族；旧的单项 PowerShell 安装器仍可
用于兼容和诊断，但根级流程不会重复调用它们。

只安装所需子集时：

```cmd
安装可恢复音源.cmd -ResourceFamily vcsl
安装可恢复音源.cmd -ResourceGroup freepats
```

可用 ID、所需空间和本机缺失状态以 `-PlanOnly` 输出为准。完整统一恢复清单约需
下载 7.17 GiB、安装与派生后约占 9.86 GiB；为归档缓存、同卷 staging 和原子发布
建议至少预留 24 GiB。实际剩余量以本机计划为准。

`-LegacyOnly` 现仅用于安装可选的项目本地 FluidSynth 兼容运行库，不处理 74 件
外部采样资源；核心首次出声和正式专用乐器不会靠它兜底。

## 下载与安装安全

下载先写入 `音源\下载缓存\<归档>.part`，支持断点续传。服务器不支持断点或返回
不可用区间时，恢复器只会自动重启一次受控临时下载；再次失败会保留 `.part` 并
给出错误。确认所选临时下载可以从零开始时使用：

```cmd
安装可恢复音源.cmd -ResourceFamily vcsl -RestartDownload
```

该开关只清理所选资源族受控的 `.part`，不会删除已验证缓存或正式音源树。

归档使用固定 SHA-256，或固定提交加完整解压树摘要验证。恢复器先在同卷临时目录
构建，全部检查通过后再原子发布；已存在且匹配的目录只复核，不匹配的目录不会被
合并或覆盖。并发安装使用进程锁与 no-clobber 发布，不要求修改 Windows 长路径
注册表。

## 兼容 SoundFont

GeneralUser GS 与 TimGM 不属于默认或可信乐器链。只有兼容旧工程或测试
SoundFont 后端时，才显式执行：

```powershell
.\安装通用音源.ps1 -InstallLocalCompatibilitySoundFonts
```

GeneralUser GS 的上游说明承认部分样本来源无法完全确认；TimGM 的 GPL-2.0 条款
没有明确的渲染音频输出例外。二者仅用于本机兼容和测试，不会在专用资源缺失时
被静默选用。

## 许可边界

恢复器从公开上游下载到使用者本机，天籁不镜像或重打包第三方采样。许可证准入、
音色质量和默认可信策展是相互独立的状态；被隔离的资源不会因调整普通发现选项而
自动放行。

VPO 等混合许可资源按固定官方发行包在本机安装，不能由天籁重新分发原始采样。
详情见 [音源许可政策](音源许可政策.md) 和
[VPO 音源许可与安装说明](VPO音源许可与安装说明.md)。

发布音乐前，请检查渲染结果旁的 `许可与署名.json/.txt`，并同时确认输入作品和
第三方资源的权利条件。

## 常见问题

### 找不到受支持的 Python

确认安装的是 64 位 CPython 3.11–3.14，并在新开的命令提示符中运行：

```cmd
py -0p
```

### 环境来自 Linux / macOS 或已经损坏

Windows、Linux / WSL 与 macOS 不能共用 `.venv`。移开不适用的虚拟环境后重新运行
`安装运行环境.cmd`。

### 某件乐器无法渲染

先运行 `检查运行环境.cmd`。如果资源为 `missing`，使用
`安装可恢复音源.cmd -PlanOnly` 查找对应资源族；如果为 `invalid`，不要用其他
音色替代，应根据报告修复不完整安装。

### 下载中断

直接重跑原命令会优先继续受控的 `.part`。只有确认需要从零下载时才使用
`-RestartDownload`。
