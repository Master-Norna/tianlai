# 渲染后自检

渲染后自检检查的是已经写入磁盘、将要交给用户的 PCM WAV，而不是渲染器中的
临时浮点数组。它是一层严格的基础质量门，但不负责决定一段音乐是否好听，也不
会自动归一化、滤波、修相位、剪尾或修改乐谱。

## 两类结论

自检把结论分为两类，二者不能互相冒充：

- **硬合同**处理可以客观证明的损坏或矛盾，例如 WAV 无法完整读取、容器或位深
  错误、采样率/声道/帧数与演奏计划不符、报告或音频 Hash 被篡改，以及计划明确
  包含正力度发音事件但最终文件只有数字静音。这类错误会阻止不完整的一代产物
  发布，不能用通用 `force` 参数绕过。
- **创作者复核项**记录有技术风险、但也可能是有意创作的现象，例如真实峰值余量
  不足、DC、单声道折叠抵消、极端声道不平衡、近似静音、满幅平台和疑似尾音
  截断。它们不会自动改变音频，也不会因为一种通用审美而阻断作品。

量化前的 NaN、Infinity 和超过 `[-1, 1]` 的采样仍由渲染器原有硬门负责。写盘后
自检不能从已经量化的 PCM 可靠反推这部分事实，因此不会替代原有检查。

## 产物与绑定

合奏、项目候选和 MCP 渲染始终生成：

```text
合奏.wav
渲染后自检.json
渲染回执.json
```

新生成的 v3 渲染回执以 SHA-256 绑定自检报告；报告再绑定准确的 WAV、规范化演奏
计划、音频格式、测量算法版本和判定政策版本。回执仍最后发布，任何暂存分析、
验证或发布失败都不会把半套新产物冒充成完整候选。旧 v2 回执仍可按原合同验证，
但不会被改写成一份并不存在的历史自检。

单乐器 `tianlai render` 在 WAV 旁生成：

```text
<文件名>.wav.渲染后自检.json
```

它与 WAV、许可证 JSON 和人类可读署名文本一起事务式发布，WAV 仍是最后的提交
标记。

## 测量内容

报告至少记录：

- WAV/PCM24/双声道结构、采样率、帧数、字节数与 SHA-256；
- 分声道与总体 sample peak、RMS、crest factor、DC、数字零和满幅统计；
- L/R 相关性、Mid/Side 能量、单声道折叠损失与声道平衡；
- 首尾窗口、最终采样、末帧跳变、最长数字零区和峰值位置；
- ITU-R BS.1770-5 / EBU Mode 的 Integrated LUFS、最大 Momentary 与
  Short-term loudness；
- Annex 2 带限过采样 True Peak；
- EBU Tech 3342 Loudness Range（短于 60 秒时明确标为不稳定，只作描述）。

机器可读结构见 [`post-render-check.schema.json`](../schemas/post-render-check.schema.json)。

测量使用有界内存流式读取，不把长作品整体复制进 RAM。报告不写时间戳、耗时、
绝对路径或本机身份，因此相同输入在不同输出目录和冷热缓存下仍可复核。
首版标准响度与 True Peak 实现只对项目正式默认的 `48 kHz` 输出声明合规；其他
受支持采样率仍执行完整结构、sample-domain、DC、立体声与边界检查，并把标准指标
明确标为 `unavailable`，不会用未经验证的近似值冒充 BS.1770 结果。

## 如何理解响度与真实峰值

BS.1770 给出的是响度与 True Peak 的测量算法，不是适用于所有音乐的唯一响度
目标。EBU R 128 的 `-23 LUFS` 面向广播节目归一化；它不能用来拒绝所有不在该
数值附近的音乐。LRA 同样没有跨风格通用的硬上限。

报告会把 True Peak 高于常见 `-1 dBTP` 分发余量线的结果列为高可信复核项；
其中超过 `0 dBTP` 的重建波形具有更直接的过载风险。后续滤波、编码或播放链仍
可能进一步抬高峰值，但首版不会因此替创作者判定作品无效。
面向特定平台正式发行时，应再按该平台的交付规范选择目标响度和峰值余量。

## 人工听审仍然必要

机器可以稳定找到损坏、身份错配和风险候选，却不能可靠判断音色是否精致、动态
是否感人、尾音是否符合句法，或一个瞬态究竟是爆音还是刻意打击。点击、掉音、
频谱异常和尾音判断尤其需要结合事件时间、分轨与实际收听；自检报告只提供可定位
证据，不把主观判断伪装成数学定理。
