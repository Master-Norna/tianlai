# Current capabilities and limitations

> Version: `0.6.0rc1`
>
> Updated: 2026-08-02

This page describes functionality that users can rely on and its known
boundaries. The current `tianlai-doctor` result is authoritative for instrument
and sound-source availability on a particular computer.

## Product scope

Tianlai is a local, editable, and reproducible workspace for music rendering
and iteration:

```text
Import score → choose instrumentation explicitly → render an immutable candidate
    → map a heard timestamp back to events → edit a local part of the score
    → render a second candidate → machine comparison + human A/B listening
```

The CLI and MCP share the same score, instrumentation, rendering, and candidate
contracts, while file permissions and default output locations differ. See
[From score to second render](从乐谱到第二次渲染.en.md) for the complete tutorial.

## Platform support

| Environment | Supported scope |
| --- | --- |
| Windows 10/11 x64 | Complete reference platform: minimal installation, every resource-restoration entry point, CLI, MCP, and first sound |
| Linux / WSL x86_64 | Isolated environment, diagnostics, programmatic instruments, CLI, MCP, portable self-checks, and cross-platform restoration entry points for all 74 external resources |
| macOS 15 / 26 `arm64` / `x86_64` | Isolated native environment, diagnostics, programmatic instruments, CLI, MCP, portable self-checks, and cross-platform restoration entry points for all 74 external resources; both macOS 15 architectures have a configured CPython 3.11–3.14 matrix, while both macOS 26 architectures revalidate 3.14; the actual post-merge CI result is authoritative |
| CPython | 64-bit CPython 3.11–3.14 |

The macOS contract accepts native processes only; both the bootstrap and doctor
detect and reject Rosetta translation.

`0.6.0rc1` compares Windows 8.3 short paths and long paths through canonical
file identity and fixes Python source checkout to LF. The release builder still
rejects symbolic links and reparse points before resolving path identity.

The cross-platform restorer covers all 74 external resources in 15 families.
Users still download large third-party archives locally under their respective
upstream licenses, and ordinary CI does not download them. A missing or
mismatched resource never triggers silent timbre substitution. See
[Linux / WSL quick start](Linux快速开始.en.md) and
[macOS quick start](macOS快速开始.en.md).

## Sound entries and resources

The project registers 103 formal sound entries and one reference oscillator
used only for self-checks:

- 29 use project-authored DSP, synthesis, or procedural sound and need no
  third-party audio assets.
- 74 depend on external public resources; the source package does not carry
  these large samples.
- Windows, Linux, and macOS provide one root-level Python restoration path for
  all 74 entries.
- The manifest freezes the public upstream, license, archive or commit
  identity, installed-tree digest, and evidence files for 15 resource families.
- An available platform entry point does not mean large resources are already
  downloaded or that every real-sample listening check has run on that host.

A missing resource makes rendering fail explicitly instead of substituting a
generic GM SoundFont. Run diagnostics first, then use the platform guide to
read the plan and install only the resources needed.

## Quality states

The currently bound version of every one of the 103 sound entries completed an
isolated single-instrument, single-timbre listening check and is therefore
marked `quality_tier=formal`. The term does not mean all of the following are
complete:

- every pitch, dynamic, articulation, and Round Robin combination;
- every multi-instrument orchestration, mix, and hall combination;
- expert evaluation of every detail of the real instrument;
- permission to redistribute third-party resources;
- automatic ideal sound for an arbitrary work.

`collaboration_review_status=untested` means the entry still needs listening in
the context of a real ensemble and work. `strict_hq` is a fail-closed gate when
precise evidence is unavailable, not an automatic audio-quality enhancement.

## Implemented capabilities

### Import and editable scores

- `project-import` handles MIDI, MusicXML/XML, and MXL through one interface.
- Successful import produces score v1, an import report, and a non-executable
  roster draft.
- Source semantics that cannot be represented losslessly are reported or
  rejected under an explicit loss policy.
- Score v1 uses stable `event_id` values and can preserve MusicXML `staff` and
  `voice`.
- `score-slice`, `score-patch`, and `score-compare` support bounded reads,
  atomic edits, and version comparison.

Neither MIDI nor MusicXML is a universal lossless input. The import report is
authoritative for pedal, pitch bend, lyrics, layout, vendor controls, and other
content beyond the current model.

### Instrumentation, rendering, and candidates

- Every ordinary part must select an instrument explicitly; a percussion part
  must select a kit explicitly.
- `project-render` creates a new unique candidate by default and does not
  overwrite an old result.
- A candidate binds its score, roster, render profile, performance plan, audio,
  receipt, and attribution sidecars.
- `candidate-locate` maps a timestamp from the actual candidate to events.
- `candidate-compare` distinguishes score, instrumentation, configuration,
  plan, and mix changes.
- The stem cache can accelerate a remix that changes only gain, pan, seats,
  hall, master, or normalization.

After a candidate is used for listening, location, or comparison, treat it as
an immutable snapshot. Make changes in the score, roster, or render profile and
produce a new generation.

### AI and MCP

MCP provides contract reading, instrument discovery, import, explicit
instrumentation, preflight, rendering, location, local editing, and candidate
comparison. Only `render` writes audio. File-based import is restricted by
explicit input roots; connecting an agent does not grant it whole-computer file
access.

See the [MCP interface](MCP.en.md) for the complete tool set and client setup.

## Known limitations

### Listening cannot be automated away

Technical reports help identify clipping, range, frequency-band, balance, or
candidate differences. They cannot decide whether a melody, structure,
orchestration, or work succeeds. Final versions still need human A/B listening.

### Audio quality depends on resources

Public sound sources differ in sample quality, dynamic layers, articulations,
and coverage. Programmatic synthesis is easier to keep deterministic and
continuous but does not reproduce every detail of a real instrument.

### A first render may be slow

Long works, high sample rates, and many parts can take several minutes and
substantial peak memory. Caches mainly accelerate later remixes. A note,
articulation, resource, or effective instrument-parameter change still
re-executes the affected stems.

### Local resource states differ

“An installer exists” does not mean the resource has been downloaded and is
complete. The source package contains no large samples. Run diagnostics before
use; repair partial installations, digest mismatches, or missing physical
license evidence instead of treating them as an ordinary absence.

## Licenses and output

Project-authored code, DSP, CLI/MCP, schemas, tests, and configuration are
Apache-2.0. Third-party samples, input works, and final audio retain their own
rights status. Tianlai does not acquire copyright in user music by rendering it.

Before publishing music, inspect `许可与署名.json/.txt`, rights in the input work,
and upstream resource terms. See the
