# Sound-source licensing and attribution policy

> **Translation notice:** This English page is an informational translation of
> the project-authored [Chinese source text](音源许可政策.md). If wording diverges,
> the Chinese source describes project policy. Original upstream license texts
> and retained physical evidence—not this summary—govern third-party material.

Project code is Apache-2.0. Input works, output music, and third-party sound
sources retain their own rights conditions. Intended non-commercial use does
not lower provenance or licensing requirements. A resource is not accepted
because similar projects use it, it circulates widely online, or enforcement
seems unlikely. Tianlai must be able to demonstrate its use path with a pinned
upstream source, original license text, and digests of the actual files.

New third-party recordings are accepted by default only under:

- `CC0-1.0`; or
- `CC-BY-3.0` / `CC-BY-4.0` with a clearly identified author, source, and
  attribution requirement.

Existing resources under other public licenses remain managed individually
under their original license and frozen evidence. A free download, a project
that currently charges no fee, or a directly accessible webpage does not imply
permission to copy, modify, or redistribute a new resource. `CC-BY-NC`, unknown
provenance, no license, material extracted from finished music, and resources
with conflicting licenses do not enter new candidate instruments by default.
Any necessary exception requires separate review and isolation from code,
public sound-source directories, and distributions.

External sound-source manifests use three controlled states. A resource within
the allowlist is `approved`. A resource that predates the allowlist and may be
retained only under its frozen evidence and original license is
`grandfathered`. A resource is `quarantined` when the intended music output
cannot be shown lawful, the install path cannot be tied to a trustworthy
upstream, or license terms conflict. Both non-approved states are recorded per
instrument in the canonical
[`音源许可例外.json`](音源许可例外.json). A `quarantined` resource cannot enter the
trusted instrument catalog or a published resource collection. This exception
registry records existing facts and cannot enlarge an original license grant;
its human-readable explanations are currently maintained in Chinese, while
status, license identifiers, evidence paths, and SHA-256 values are
language-independent.

`local-compatibility-only` is a runtime channel, not a fourth license state that
disguises insufficient evidence. Such a SoundFont is not registered as a
project instrument and does not enter default installation, public catalog or
capabilities, MCP, trusted routing, or the collaboration layer. A user may test
it locally only through an explicit file path. GeneralUser GS remains within
this boundary because its upstream discloses that some sample provenance cannot
be established completely. TimGM remains within it because GPL-2.0 does not
state a clear rendered-audio output exception. They never silently fall back to
each other, and their renders are not Tianlai public-release artifacts.

An official sample library composed of several public licenses may be used as
an existing `grandfathered` resource without Tianlai reconstructing a separate
redistribution-rights chain for every WAV only when all of these are true:

1. The installer obtains one complete pinned release solely through the author
   or project's official download path.
2. Archive size, SHA-256, merged-tree digest, and license evidence are frozen.
3. The source is extracted unchanged only on the user's computer; Tianlai does
   not host a mirror, extract a subset, modify it, or repackage it.
4. Upstream terms clearly allow the release to be used to make and publish
   music, and required license/attribution files remain with the local install.

This rule answers only whether an official package may be installed in its
documented way and used for rendering. It does not grant Tianlai permission to
republish the sample library. Mirroring, trimming, combining, format conversion,
or separate SFZ/WAV publication requires a new per-source and per-derivation
review. Insufficient evidence returns the resource to `quarantined`.

A “published resource collection” means original or reorganized samples, SFZ,
or an extractable sound-source package carried or hosted by Tianlai. It does
not include an installer that sends the user directly to the official complete
upstream package, nor is it the same as ordinary rendered music. When upstream
evidence permits music creation, the project may publish normal finished music
or short listening examples for public review. It must not promote or repackage
dry notes, stems, or chromatic full-range auditions as reusable sample assets.

Rights in third-party compositions are managed separately from instrument
licenses. A user may employ such a work for a locally controlled evaluation
only when they possess the required rights. Public demonstrations and public
review use original material, material under an explicit open license, or
material for which both the work and its exact score edition or encoding are
lawfully usable.

Every new sound source retains at least:

1. the official project page, persistent DOI, or author's release page;
2. a pinned commit, pinned version, or checksummed dataset file;
3. the original license text and author, performer, or library name;
4. SHA-256 values for the SFZ, sample set, and license evidence actually used;
5. an explicit account of remapping, tuning, denoising, splitting, or format
   conversion;
6. an installer that writes only under root `音源/`, verifies in a temporary
   directory, publishes atomically, and never overwrites an existing tree.

The lightweight source package includes no actual sound sources, virtual
environment, render output, or download cache. A separately distributed sample
resource or derived resource package must retain the applicable attribution,
license links, source links, and change notices. This also applies to
non-commercial distribution.

Every released external-instrument manifest whose applicable terms include BY,
BY-SA, Sampling Plus, or another attribution condition must contain non-empty
`creator` and `attribution` fields supported by first-party evidence. A mixed
licence is handled conservatively when any component that may be used carries
such a condition. CC0 sources may retain the same fields for provenance, but
the text must make clear that credit is not a legal requirement and does not
imply endorsement by the upstream author or project. Carrying these fields into
a sidecar preserves existing evidence; it does not replace component-specific
licence analysis.

Every actual render generates machine-readable `许可与署名.json` and concise
human-readable `许可与署名.txt`. A single-instrument WAV uses adjacent
`<filename>.许可与署名.json/.txt`; an ensemble stores both at the finished
directory root. These sidecars list only instruments used in that render, not
the global 103-entry license catalog. The JSON binds the current ensemble,
stems, or single WAV by SHA-256. A missing author, upstream, origin, or license
field stays `null` and produces a warning; it is never guessed from a filename
or general knowledge. Retain the sidecars with published output and continue
to check every upstream license text. An automatically generated inventory
cannot enlarge an upstream grant.

Project-authored DSP provenance is not inferred from an instrument's type or
name. A sidecar reports “project-authored DSP / no third-party samples” only
when the manifest simultaneously declares
`provenance_kind=project_authored_dsp`,
`implementation_license=Apache-2.0`, `external_audio_assets=[]`,
`audio_asset_license=not_applicable`, and `license_status=approved`. If any one
is missing or inconsistent, Tianlai treats provenance as incomplete and keeps
the warning. See [`OUTPUT_RIGHTS.en.md`](../OUTPUT_RIGHTS.en.md) for the full
boundary between code, input works, and output.

License evidence is a minimum admission condition, not proof of audio quality.
A resource must independently pass range coverage, end-to-end tuning,
dynamic/round-robin behavior, attack and release, pop/clipping checks,
determinism, and human blind listening.
