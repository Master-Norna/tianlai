# From score to second render

This is the recommended main workflow. The goal is not merely one WAV, but a
creative loop that remains editable and makes before/after versions comparable:

```text
Install → import → confirm instrumentation → candidate 1 → locate problem
    → edit score → candidate 2 → A/B
```

Run all commands below from Command Prompt (`cmd.exe`) in the source-release
root. The multiline continuation character is `^`. Windows users can call
`天籁.cmd` directly; it always uses the project's own `.venv` and does not
pollute system Python.

## 1. Install and inspect

```cmd
安装运行环境.cmd
检查运行环境.cmd
```

The first command creates `.venv`, installs the core and MCP, runs diagnostics,
and produces a first-sound WAV with the sample-free reference oscillator. It
does not download several gigabytes of sound sources.

Diagnostics separately report:

- whether code and directories can run;
- how many of the 103 formal sound entries have resources that are `ready`,
  `missing`, or `invalid`;
- whether the trusted palette is usable;
- whether a missing resource has a restoration installer.

A missing sample resource makes rendering fail explicitly instead of silently
substituting a generic GM sound. Twenty-nine project-authored DSP entries need
no external samples. All other 74 external resources have a root restoration
path. First inspect licenses, size, and local state:

```cmd
安装可恢复音源.cmd -PlanOnly
```

After confirmation, run `安装可恢复音源.cmd`. With no arguments, it processes all
74 external resources; a resource family or group can select a smaller subset.
Installer completion means the selection passed its pinned archive or
complete-tree evidence. It does not grant permission to redistribute
third-party samples. `检查运行环境.cmd` remains authoritative for the ready count.

### Run the bundled loop first

If you do not yet have MIDI/MusicXML, use `examples/最小闭环.musicxml` to learn
the workflow. It has one `P1` part and these companion files:

- `最小闭环.render-profile.json`: a lightweight deterministic candidate
  profile;
- `最小闭环.slice-query.json`: reads a bounded fragment of `P1`;
- `最小闭环.patch.json`: changes the final G4 to a stronger F4;
- `乐器/测试工具/参考振荡器`: no samples required.

Replace “某曲” with “最小闭环” in the sections below and import with:

```cmd
天籁.cmd project-import ^
  --input "examples\最小闭环.musicxml" ^
  --output "output\入门闭环\导入-01"
```

Then copy these two commands to confirm instrumentation and produce the first
sound:

```cmd
天籁.cmd roster-promote ^
  --score "output\入门闭环\导入-01\最小闭环.score.json" ^
  --draft "output\入门闭环\导入-01\最小闭环.roster-draft.json" ^
  --assign "P1=测试工具/参考振荡器" ^
  --open-palette ^
  --output "output\入门闭环\最小闭环.roster.json"
```

```cmd
天籁.cmd project-render ^
  --score "output\入门闭环\导入-01\最小闭环.score.json" ^
  --roster "output\入门闭环\最小闭环.roster.json" ^
  --render-profile "examples\最小闭环.render-profile.json" ^
  --title "最小闭环"
```

On success, `mix_wav` in the terminal is the absolute path to the first sound.
Use the companion query for slicing and the companion patch for editing. The
second `project-render` must still include the same `--render-profile`. This
fixed patch binds only the original score imported from this example; never use
it on your own score. Starting with section 2, the paths are templates for a
user work. Do not mechanically apply `乐谱\曲目\某曲` paths to the
`output\入门闭环` example.

## 2. Import a score into a new project

Notation software such as MuseScore usually exports MusicXML. DAWs and notation
software commonly export standard MIDI. MusicXML is better at preserving score
structure, while MIDI is better at preserving performance timing and per-note
velocity. Both may contain semantics Tianlai cannot currently represent
losslessly.

```cmd
天籁.cmd project-import ^
  --input "乐谱\曲目\某曲\MusicXML\某曲.mxl" ^
  --output "乐谱\曲目\某曲\导入-01"
```

For MIDI, change `--input` to a `.mid` or `.midi` file. By default the command:

- produces `某曲.score.json`, `某曲.import-report.json`, and
  `某曲.roster-draft.json`;
- records both the source-file byte hash and canonical score hash in the import
  report and roster draft;
- refuses to overwrite an existing import directory;
- applies `--loss-policy reject` to performance semantics it cannot preserve;
- returns bounded candidate-instrument hints without granting routing authority.

When default `reject` encounters unsupported semantics, it fails atomically and
publishes no partial score, report, or draft. If a human reviews the reported
degradation and accepts it, rerun explicitly into a new directory:

```cmd
天籁.cmd project-import ^
  --input "乐谱\曲目\某曲\MusicXML\某曲.mxl" ^
  --output "乐谱\曲目\某曲\导入-02" ^
  --loss-policy warn
```

After `warn` succeeds, do not rely on a one-line success message. Keep and read
the complete `import-report.json`. Repeats, grace notes, pedal, pitch bend,
vendor controls, and other information omitted from score cannot be restored
automatically by later rendering.

## 3. Confirm every part's instrument explicitly

Open `roster-draft.json` and inspect each part's ID, range, percussion flag, and
`routing_hints`. Candidates narrow the search; the creator confirms the final
route.

Ordinary melodic parts may be assigned one by one on the command line:

```cmd
天籁.cmd roster-promote ^
  --score "乐谱\曲目\某曲\导入-01\某曲.score.json" ^
  --draft "乐谱\曲目\某曲\导入-01\某曲.roster-draft.json" ^
  --assign "Piano=键盘乐器/钢琴" ^
  --assign "Violin=管弦乐/弦乐组/小提琴" ^
  --output "乐谱\曲目\某曲\某曲.roster.json"
```

The left side of `--assign` must exactly equal `score.parts[].id`, which is the
draft's corresponding `assignment.part`; do not use display-only
`parts[].name`. For a drum kit or a project needing roles, gains, seats, groups,
and collaboration relationships, use `assignments.json`:

```json
[
  {
    "part": "Melody",
    "instrument": "管弦乐/弦乐组/小提琴",
    "gain_db": -3,
    "role": {
      "function": "lead",
      "prominence": "foreground"
    }
  },
  {
    "part": "Drums",
    "kit": {
      "C2": "现代鼓组/底鼓",
      "D2": "现代鼓组/小军鼓"
    }
  }
]
```

```cmd
天籁.cmd roster-promote ^
  --score "...\某曲.score.json" ^
  --draft "...\某曲.roster-draft.json" ^
  --assignments "assignments.json" ^
  --output "乐谱\曲目\某曲\某曲.roster.json"
```

The current trusted palette is the default. To use another non-quarantined
formal entry, add `--open-palette` explicitly during roster confirmation. This
does not release license-evidence quarantine or local SoundFont compatibility
entries.

## 4. Generate the first immutable candidate

```cmd
天籁.cmd project-render ^
  --score "乐谱\曲目\某曲\导入-01\某曲.score.json" ^
  --roster "乐谱\曲目\某曲\某曲.roster.json" ^
  --title "某曲"
```

The versioned `preview-v1` profile is the default: deterministic seed, shared
hall, peak normalization to `-1 dBFS`, saved stems, and raw-stem cache enabled.
Output goes to:

```text
output/候选/<sanitized title>/<unique candidate ID>/
```

The candidate directory contains:

- `合奏.wav` and optional `分轨/`;
- `score.json`, `roster.json`, and `render-profile.json`;
- `演奏计划.json` and `渲染回执.json`;
- `渲染后自检.json`, binding the final PCM, standards-based loudness/True
  Peak measurements, and graded risks;
- `许可与署名.json/.txt`;
- `候选.json`, written last.

`候选.json` binds these files to the actual performance plan. A same-named
title does not overwrite an old result by default and no longer causes an MCP
output collision.

The candidate is first rendered completely in private staging beside the final
directory. The engine streams the final PCM back from disk and recursively
verifies the receipt-bound performance plan, self-check, ensemble, stems,
license sidecars, attribution, and diagnostics; it publishes atomically and
verifies again at the final path. Controlled replacement binds
both the old receipt and the old candidate manifest seen during preparation,
rejecting stale authorization from a concurrent writer. An ordinary exception
retains or restores the previous complete candidate.

An `error` in the self-check means only a demonstrable contract failure. True-
peak headroom, loudness, DC, phase, channel, and tail candidates are non-
blocking review findings. See [Post-render self-check](渲染后自检.en.md) for the
complete boundary.

## 5. Map a heard timestamp back to notes

Suppose you hear a problem at `34.2` seconds:

```cmd
天籁.cmd candidate-locate ^
  --candidate "output\候选\...\candidate-..." ^
  --at 34.2 ^
  --output "output\诊断\34.2秒.json"
```

This command reads the saved candidate's receipt and performance plan. It does
not recompile a current project that may already have changed. It returns:

- events gated on at that second;
- recently ended events that may still contribute sample release or hall tail;
- events about to sound;
- `event_id`, part, instrument, pitch, bar, beat, and every binding hash.

The tail list identifies candidate sources and does not pretend to prove
sample-by-sample causality. Use stems and human listening as well.

## 6. Edit score with conflict protection

Read a bounded fragment first. Save this query as `slice-query.json`:

```json
{
  "kind": "tianlai.score_slice_query",
  "schema_version": 1,
  "part_ids": ["Violin"],
  "bar_range": {"start": 12, "end": 14},
  "max_notes": 128
}
```

```cmd
天籁.cmd score-slice ^
  --score "乐谱\曲目\某曲\导入-01\某曲.score.json" ^
  --query "slice-query.json" ^
  --output "slice-result.json"
```

The returned `score_sha256` is the edit baseline. Save this as `patch-01.json`:

```json
{
  "kind": "tianlai.score_patch",
  "schema_version": 1,
  "base_score_sha256": "64-character hash copied from slice-result.json",
  "operations": [
    {
      "op": "update_note",
      "event_id": "violin-0042",
      "expect": {"pitch": "B5", "dynamic": "f"},
      "changes": {"pitch": "A5", "dynamic": "mf"}
    }
  ]
}
```

```cmd
天籁.cmd score-patch ^
  --score "乐谱\曲目\某曲\导入-01\某曲.score.json" ^
  --patch "patch-01.json" ^
  --output "乐谱\曲目\某曲\某曲.rev02.score.json" ^
  --result-output "乐谱\曲目\某曲\某曲.rev02.patch-result.json"
```

A hash or old `expect` mismatch rejects the entire patch instead of applying
half. Preserve the original `event_id` when moving a note or changing pitch,
velocity, or duration. The engine assigns a new note's ID deterministically.
Creators comfortable with JSON may edit a copy directly, but must preserve IDs
and avoid rerunning an old generator that overwrites the file.

## 7. Generate and compare the second candidate

Render the new score and identify the first candidate as its parent:

```cmd
天籁.cmd project-render ^
  --score "乐谱\曲目\某曲\某曲.rev02.score.json" ^
  --roster "乐谱\曲目\某曲\某曲.roster.json" ^
  --title "某曲" ^
  --parent-candidate "candidate-第一个候选ID"
```

When only gain, pan, seats, hall, master, or normalization changes, the
identity-verified raw stem cache can remix directly. Changing a part's notes,
articulations, source, instrument parameters, or DSP invalidates only the
related caches.

```cmd
天籁.cmd candidate-compare ^
  --before "output\候选\...\candidate-第一个" ^
  --after "output\候选\...\candidate-第二个" ^
  --output "output\诊断\候选1-候选2.json"
```

The comparison separates score, roster, render profile, performance plan, and
final mix identity changes. Then directly A/B the `合奏.wav` in both
directories. Machine differences confirm what changed; they do not decide
which version sounds better.

## 8. Return to notation software

Score is Tianlai's authoritative editable intermediate form. To continue in
MuseScore or a DAW, export a MIDI copy with explicit loss reporting:

```cmd
天籁.cmd export-midi ^
  --score "乐谱\曲目\某曲\某曲.rev02.score.json" ^
  --roster "乐谱\曲目\某曲\某曲.roster.json" ^
  --output "乐谱\曲目\某曲\MIDI\某曲.rev02.mid"
```

By default, blocking semantic loss writes only a loss report and no MIDI. Pass
`--allow-lossy` only after reviewing the report. MIDI does not preserve
Tianlai's stable event identity, every articulation, microtones, phrases, or
dedicated-instrument semantics. It is an interchange/editing copy, not a
lossless inverse of score.

## What to inspect first after a failure

1. `检查运行环境.cmd`: distinguish code, trusted-catalog, and actual
   sound-source problems.
2. `import-report.json`: inspect semantic loss during import.
3. `roster-promote` errors: confirm every part has exactly one explicit route.
4. `candidate-locate`: locate the candidate actually heard; do not guess from a
   modified project.
5. `许可与署名.json`: verify the resources actually used before publishing.
6. [`docs/当前状态.en.md`](当前状态.en.md): confirm unvalidated scope and known
   performance limitations.
