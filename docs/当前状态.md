# 当前能力与限制

> 版本：`0.5.0rc2`
>
> 更新日期：2026-07-28

本页说明使用者能够依赖的功能与已知边界；本机乐器和音源是否可用，以
环境诊断命令 `tianlai-doctor` 的当次结果为准。

## 产品定位

天籁是一套本地运行、可编辑、可复算的音乐执行与迭代工作台：

```text
导入谱面 → 明确配器 → 渲染不可变候选
    → 从听到的秒数定位事件 → 局部修改 score
    → 渲染第二个候选 → 机器比较 + 人耳 A/B
```

CLI 与 MCP 使用同一套乐谱、配器、渲染和候选合同，但文件权限与默认输出位置
不同。完整教程见 [从乐谱到第二次渲染](从乐谱到第二次渲染.md)。

## 平台支持

| 环境 | 支持范围 |
| --- | --- |
| Windows 10/11 x64 | 完整参考平台；支持最小安装、全部资源恢复入口、CLI、MCP 与首次出声 |
| Linux / WSL x86_64 | 支持独立环境、环境诊断、程序音色、CLI、MCP、portable 自检，以及 38 件统一恢复资源 |
| CPython | 支持 64 位 CPython 3.11–3.14 |

Linux 上另有 36 件资源仍只有 Windows 安装器，环境诊断会标记为
`unavailable_on_platform`，不会静默替换音色。详情见
[Linux / WSL 快速开始](Linux快速开始.md)。

## 声音入口与资源

项目登记 103 个正式声音入口，另有一个只用于自检的参考振荡器：

- 29 件采用项目自研 DSP、合成或程序拟音，不需要第三方音频资产；
- 74 件依赖外部公开资源，源码包不携带这些大型采样；
- Windows 为全部 74 件提供根级恢复入口；
- Linux 提供其中 38 件统一资源的跨平台恢复入口。

资源缺失时渲染会明确失败，不会自动换成通用 GM SoundFont。先用环境诊断查看
状态，再按平台文档读取计划和安装所需资源。

## 质量状态

103 个声音入口的当前绑定版本均完成了单乐器、单音色独立试听，因此标记为
`quality_tier=formal`。这个术语只描述当前绑定音色，不表示以下事项已经全部
完成：

- 所有音高、力度、奏法与 Round Robin 组合；
- 所有多乐器编配、混音与厅堂组合；
- 专家对每种真实乐器细节的评价；
- 第三方资源的再分发授权；
- 任意作品都能自动获得理想听感。

`collaboration_review_status=untested` 表示合奏语境仍需按作品实际试听。
`strict_hq` 是缺少精确证据时拒绝执行的门禁，不是自动增强音质的开关。

## 已实现能力

### 导入与可编辑乐谱

- `project-import` 统一处理 MIDI、MusicXML/XML 与 MXL；
- 成功导入生成 score v1、导入报告和不可执行的 roster 草稿；
- 无法无损表达的源语义会按明确的 loss policy 报告或拒绝；
- score v1 使用稳定 `event_id`，并可保留 MusicXML 的 `staff` 与 `voice`；
- `score-slice`、`score-patch` 和 `score-compare` 支持有界读取、原子修改和
  版本比较。

MIDI 与 MusicXML 都不是无损万能入口。踏板、弯音、歌词、排版和厂商控制信息等
超出当前模型的内容，以导入报告为准。

### 配器、渲染与候选

- 每个普通声部必须显式选择乐器，打击声部必须显式选择 kit；
- `project-render` 默认创建新的唯一候选，不覆盖旧结果；
- 候选绑定 score、roster、render profile、演奏计划、音频、回执与许可旁车；
- `candidate-locate` 从实际候选秒数定位事件；
- `candidate-compare` 区分乐谱、配器、配置、计划和混音变化；
- 分轨缓存可加速只改变 gain、pan、座位、厅堂、master 或归一化后的重混。

候选用于试听、定位或比较后，应视为不可变快照。修改应回到 score、roster 或
render profile，再产生下一代候选。

### AI 与 MCP

MCP 提供合同读取、乐器发现、导入、显式配器、预检、渲染、定位、局部修改和
候选比较。只有 `render` 写入音频；文件型导入受显式输入根限制，Agent 不会因为
连接服务就获得整机文件访问权限。

完整工具和客户端配置见 [MCP 接口](MCP.md)。

## 已知限制

### 听感不能自动完成

技术报告可以帮助发现削波、音域、频带、平衡或候选差异，但不能判断旋律、结构、
配器和作品是否成立。最终版本仍需人耳 A/B。

### 音质受资源限制

公开音源的采样质量、力度层、奏法与覆盖范围并不一致。程序合成更容易保持确定性
和连续性，也不等于复现真实乐器的全部细节。

### 首次渲染可能较慢

长曲、高采样率和多声部项目可能需要数分钟与较高峰值内存。缓存主要加速后续
重混；音符、奏法、资源或有效乐器参数变化时，相关分轨仍需重新执行。

### 本机资源状态不同

“存在安装器”不等于资源已经下载且完整。源码包不携带大型采样，使用前请运行
环境诊断；部分安装、摘要不符或许可证据缺失都应修复，不能当作正常缺失跳过。

## 许可与输出

项目自研代码、DSP、CLI/MCP、Schema、测试和配置采用 Apache-2.0。第三方采样、
输入作品和最终音频保持各自的权利状态；天籁不会因为执行渲染而取得使用者音乐
输出的著作权。

发布音乐前，请检查 `许可与署名.json/.txt`、输入作品权利与上游资源条款。详情
见 [输出权利说明](../OUTPUT_RIGHTS.md)、
[项目名称与标识](../TRADEMARKS.md) 和
[音源许可政策](音源许可政策.md)。
