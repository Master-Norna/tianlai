# 创作工作流

v0.7 增加的是一项可选能力：让通用 Agent 在持久创作工程上多花时间，按证据反复
复核、渲染、修订和保留候选。它不是“好听目标函数”，也不是 MCP 协议本身带来的
保证。生成一段音频和创作一段音乐仍是两回事。

## 诚信边界

工作流把三类判断分开：

| 类别 | 能否自动阻断 | 含义 |
| --- | --- | --- |
| `hard_failure` | 可以 | 可信引擎合同实际复现的失败，如未分配声部、不可渲染输入。 |
| `promise_conflict` | 不可以 | 当前方案可能违背本曲宪章或已激活条款。 |
| `aesthetic_risk` | 不可以 | 结构、听感、制作或审美上的有依据假设。 |

机器可以复利地排除已知失败，却不能据此证明剩余候选“客观好听”。工作流因此明确
禁止单一审美目标、自动改谱和自动改音频。`accept` 只表示：冻结的终审者在这份
work charter、这些证据和声明的感知依据下接受了这个不可变候选。

例外不是检测漏洞。故意粗糙、失真、Lo-fi 底噪、不协和或未被规则理解的材料，可以
用目的、范围、较高价值、代价、恢复方式和证据登记例外。可信 hard failure 永远不能
被例外赦免。未选候选和未修订初稿也不会因 workflow 关闭而被删除。

## 前置条件

工作流依附于一个持久 authoring project 和一个不可变 authoring revision。它不替代
score、authoring roster 或 render profile，也不替 Agent 暗中修改它们。

Agent 应先调用：

```text
creative_workflow_guide
```

该工具返回模式、边界、work charter 模板、复核阶段、证据合同、允许决策，以及本地
官方《天籁音乐宪法 v0.2》的身份和 Hash。它不会把全文塞入每轮上下文。

如需官方条文，按明确 ID 有界读取：

```text
get_music_constitution_clauses(
  clause_ids=["C0.04", "C2.1.02", "C4.1.15"],
  language="zh-CN"
)
```

一次至多 12 条。服务先核对完整文档 SHA-256，再从明确注册表返回条文；未知 ID、
重复 ID、文档缺失或完整性不符都会拒绝。官方 activation 还会再次核对
`document_id`、`version`、`language`、`content_sha256` 和全部激活 ID。自定义宪法仍可
只按 caller 提供的 Hash 与解释绑定，但结果明确标为 `custom`，不能冒充官方文档。

## Work charter

最低可用宪章如下：

```json
{
  "title": "本曲宪章标题",
  "one_sentence_promise": "这首作品在此语境中承诺什么",
  "target_listener_and_scene": "听众、场景、媒介与监听条件",
  "primary_sovereignty": ["M"],
  "identity_kernel": {
    "invariants": ["必须可追踪的不变量"],
    "transformable_parts": ["允许改变的部分"]
  },
  "ending_contract": "结尾如何回答、改写、悬置或拒绝开头承诺"
}
```

还可声明情绪与运动向量、能量/张力曲线、记忆地标、稀缺资源、高潮特权、禁止捷径、
不确定性和终审维度。`primary_sovereignty` 使用 `M/G/H/P/T/O/N/L/R/C/X/I` 等法域
代码；它不是风格分数。

宪法是可选的。采用时只激活少量、与本曲直接相关的条款，并为每条写明
`role`、`rationale` 和本曲语境下的 `interpretation`。全开条款会让规则互相稀释，
也会把工作流退化成保守清单。

宪法也不是生成前塞给全曲的一份总提示词。v0.2 条款用于在会改变后续可能空间的
关键位置提出问题，不直接替作品生成答案。萌发材料和微小气韵无需事前逐项证明；关系
形成以后，重大、醒目或不可逆的选择才逐渐承担与尺度相称的后果。已经由作品材料解决的
地方，不必反复用条款重做一次全曲辩护。

运行时从 wheel 内 `tianlai/_resources/constitutions/` 读取经固定完整 Hash 校验的
byte-for-byte 法源副本；音乐创作参考笔记中的中英文原文继续保留，并由测试强制两处
字节同步。因此条文查询不依赖当前目录恰好存在源码仓库的 `docs/`。

## 相因治理：作品展开图、全曲镜子与有界修宪

不用 MCP 时，可以观察模型的裸创作能力；通过 MCP 新建 workflow 时，本版会像其他
主流程能力一样默认开启相因治理，同时保留显式调整或关闭入口。它不拿历史作品、
偏好案例或获奖理由教模型模仿，而是强迫模型先解释**当前这首作品**如何从自己的材料
长成完整序列：

```text
inspect_workflow_composition（取得当前有效宪章的 claim IDs）
  → 草拟作品展开图
  → inspect_workflow_composition（只读全曲镜子）
  → record_workflow_composition_map（冻结本轮展开图）
  → intent / symbolic_structure / orchestration_performance 逐题回答
      （配器复核内含轻量“成境 / Qiyun”位置审视）
  → 推导、证据、渲染与裁决
```

作品展开图按顺序列出稳定节点。每个节点说明它在全曲中的作用、依赖的宪章主张、已建立
材料、需要保持或转化的内容、声部角色变化、稀缺资源、结尾回应和开放问题。它不是固定
曲式模板；小节范围也可以暂不声明。正式候选始终是完整曲目，事件、小节和秒窗只用于
全曲内部的定位与论证，不会另存成片段成品。

全曲镜子只报告当前 score 的符号事实、展开图覆盖与可追问缺口，不评分、不改谱、也不
声称听过音频。三相复核各有固定的全曲问题，结构镜子还会追加由当前事实触发的问题。
答案必须覆盖完整问题集，并引用问题实际指向的当前 claim、节点或事件；关键节点推导
还会绑定当前有效宪章、展开图和已经回答的问题。机器只能证明这些引用与覆盖成立，不能
证明回答有音乐洞察，更不能证明作品好听。

“成境 / Qiyun”不是新增阶段，而是 `orchestration_performance` 内的一次轻量位置审视：
面对完整候选，寻找哪些位置虽然正确存在，却仍缺少流动、层次、呼吸、距离、余响或周边
生命；也必须允许结论是零新增，不能为了填满空白而机械添加点缀。微小伴生材料可以通过
删除、静音或前后候选比较审查其作用，不要求每个细节都补造宏大理由或段落级推导。只有
实际听过完整候选，才能把差异写成听审结论；否则只能记录待听审的 `aesthetic_risk` 或
假设。若修改开始改变身份核、主要和声因果、段落职能、高潮依据、结尾回应或宪章主张，
它就越过了成境的微观边界，必须转入正式修订；涉及宪章变化时继续使用既有修宪预检，
不另建阶段、账本或 Schema。位置审视的结论折入既有配器复核回答，不增加一条可打分的
“成境题”；机器可以确认提示已经给出、引用仍然有效，却不能证明模型真的想明白了。

创世宪章保持不可变；后续变化只追加到一条线性修宪账本，不再制造第二套父版本树。若
迭代意见确实要求改变某项宪章，先用 `preflight_workflow_charter_amendment` 计算受影响
主张、展开图依赖、推导、复核、证据解释和最小重构范围。预检可在 `reviewing` 期完成，
也可在 `revise` 后但 score 尚未改动时完成。提交必须逐字段回显同一预检 Hash 与精确
成本，并且早于任何替代 score 保存；范围一旦扩大就必须重新预检。修宪从下一轮生效，
下一轮必须按新 score 与有效宪章重建展开图并重新复核全曲。这使“革命”先承担完整代价，
而不是先大规模重盖、再用新宪章追认跑题。非 hard 依据还必须实际命中拟修改的主张或
集合根域；无关意见不能给修宪背书。预检把解析后的最小输入快照纳入 Hash，workflow 在
提交和历史重开时用持久记录重算影响与成本。谱面先后关系只由内部、线性的保存事件证明，
不增加一棵需要创作者管理的父版本树。

## 模式与状态

| 模式 | 用途 |
| --- | --- |
| `off` | 留下明确 opt-out；创建后即为 `disabled`。 |
| `audit` | 审查固定修订或既有候选，可建议修订，但不进入自动迭代链。 |
| `iterate` | 在预算内渲染、复核、绑定显式新修订和回滚选择。 |

主要状态迁移为：

```text
charter_pending
  → activate → map / mirror / question reviews → reviewing
  → request/render → candidate_pending → record → reviewing
  → revise → revision_pending
      → 可选修宪预检/精确成本确认（必须先于改谱）
      → bind authoring revision → reviewing → 重建本轮展开图
  → accept → completed
  → preserve/stop/terminate → stopped
```

每一步都要求 `expected_revision`。状态以完整不可变修订发布，再用小型 current pointer
做 CAS；旧修订和父链保留。普通 `open_creative_workflow` 只验证所选修订，避免每步
产生 O(n²) 历史遍历；需要审计时显式调用 `verify_creative_workflow_history`。

显式打开旧修订时，结果标记 `historical_read_only=true`；其 `next_action` 只会要求
不带 revision 重新打开 current，不会根据历史状态建议任何写操作。历史修订用于审计，
不能作为新的 CAS 写入基线。

`next_action` 根据当前已验证状态给出程序导航和建议参数，但不替终审者选择作品。

迭代预算是上限，不是创作目标。承诺已经兑现、身份核在变形中仍保持稳定、并且实质
不同的备选已经因明确前提而关闭时，应当 accept、preserve 或 stop。只剩音色偏好、
无关紧要的表面变体，或没有新证据支持的改动时，不得为了“再迭代一轮”而继续迭代。

直接终止时，只有 `budget_exhausted` 具有窄而可复验的机器语义：至少一项**正数**冻结
预算已经达到上限、当前迭代已到 fork 上限，或 workflow 历史已经到上限；设为 0 的
关闭项不构成耗尽。`no_material_improvement`、`external_blocker` 等其余理由仍是终审
authority 的声明。状态机验证权限、时序和记录形状，但不会把这些主观或外部判断冒充
成机器证明。

## 复核与证据

接受候选前，本轮必须记录四相复核：

1. `intent`
2. `symbolic_structure`
3. `orchestration_performance`
4. `render_report`

受相因治理的本轮在渲染前必须完成前三相的完整问题集；旧合同仍只要求结构和配器前置。
`render_report` 必须绑定当前候选。只有实际听过音频的
主体才可声明 `audio_audition`。stdio MCP 没有可信人类身份通道，所以 generic review
始终记录 `reviewer=agent`；它没有让模型自称 creator、listener、engine 或 validator
的参数。

普通 `record_workflow_evidence` 也固定 `reporter=agent`，schema 只允许
`promise_conflict` 和 `aesthetic_risk`。`render_measurement` 必须把 artifact Hash 与
`render_receipt`、`post_render_check` 或 `mix_report` 的明确角色绑定，不能拿任意 Hash
冒充测量证据。

hard failure 走独立可信入口：

```text
record_verified_workflow_hard_failure(issue_code=...)
```

服务端会针对本轮固定 authoring revision 重新运行 readiness，只接受其中
`decision=block` 且代码精确相等的 issue，并持久化为 validator/engine-contract 证据。
这份记录保留“当时确实失败”的历史事实，但不是永久封锁：`next_action`、渲染请求和
accept 都会在可信 readiness 边界重新复现；环境恢复后，导航会回到正常复核/渲染路径，
而不会因为旧证据仍在历史中就强迫无意义修订。

### 主张生命周期

复核、证据和例外不再只是“写进日志就算完成”。它们的稳定 ID 都由完整正文计算，
每次打开修订和验证历史都会重算；改写正文却保留旧 ID 会失败关闭。证据若引用
`event_ids` 或 `part_ids`，还会重新打开它所绑定的不可变 authoring score 校验事件、
声部及二者的对应关系。`render_measurement` 必须同时绑定当前候选、受支持的报告角色
及其 Hash；当前 `basis.reference` 仍是对测量内容的文字说明，尚未冒充可复算的
JSON selector / 数值合同。

每个新迭代决策都必须显式写出两组引用：

- `review_ids` 固定这次裁决实际采用的复核。accept 必须在所选集合中覆盖四相；若声称
  `audio_audition`，所选集合里必须有同一裁决主体真实记录的试听复核。
- `evidence_dispositions` 对本轮每条非 hard-failure 证据恰好处置一次：
  `resolved`、`accepted_risk`、`excepted`、`deferred`、`revision_target` 或
  `contested`。解决和争议必须引用独立依据，不能让证据自己证明自己；`contested`
  还必须指向另一条证据，`excepted` 必须指向确实引用该证据且目标一致的例外。

每个 disposition 的 `evidence_id` 还必须同时列入决策顶层 `evidence_ids`；`basis_ids`
所引用的 review、evidence、exception 或 derivation ID，也必须分别出现在同一决策的
`review_ids`、`evidence_ids`、`exception_ids` 或 `derivation_ids` 选择中。

accept 只允许已经 `resolved`、明确 `accepted_risk` 或合法 `excepted` 的主张；
promise conflict 不能被降格成普通风险直接接受。revise / recommend 至少要有一条
`revision_target`；`revise` 还必须填写 `expected_audible_change`。preserve / stop 可以诚实
保留 `deferred` 或 `contested`，终止记录会把这些 ID 冻结为 `open_evidence_ids`；独立
应急终止则把当前全部非 hard-failure 主张列为开放项，不伪称已经解决。历史修订缺少
这些新增字段时仍按旧合同读取，且不会被回填成“明确处置为空”。对于 `resolved`，机器
只验证依据 ID 存在且已被本次决策选择、禁止自指，并拒绝 resolved-evidence 依赖环；
它不证明“解决理由”在音乐或审美上成立。这些规则只禁止静默忽略或篡改主张，不会把
审美风险自动升级成 hard failure，也不会替创作者判断音乐好坏。

新写入的 accept 还会把一次 `acceptance_gate` 冻结进终止记录。它只复核本轮**已经记录**
的 hard-failure evidence，并绑定当时的 authoring revision Hash、候选 manifest SHA-256、
这些 hard-failure 的内容 ID，以及复核所得 readiness 结果 SHA-256（没有已记录的
hard failure 时为 `null`）。accept 要求这组已记录失败在该次复核中没有继续复现。
这是一项时间点证明，不是“当前 readiness”：以后打开或验证历史不会按机器的现状重跑
readiness，也不会据此声称未记录的新问题不存在；它更不是作品质量或审美成立的证明。

读取兼容不靠回填旧历史：基础 legacy、Claim Lifecycle、acceptance gate 与 settlement
shape 均保持原语义。`composition_governance_profile=whole-work-derivation-and-bounded-amendment-v1`
和 `revision_contract_profile=bounded-change-and-explicit-challenger-settlement-v1` 可独立存在或
组合：前者负责展开图、全曲问题和修宪，后者负责修订范围与挑战者闭环。新决策继续显式
携带 `derivation_ids` 与 `charter_settlement`；accept 必须完整清偿，preserve/stop
可部分或为空。旧 terminal accept 保持原语义，不会被伪造性回填；旧的
accept 若缺 gate 仍标记为 `legacy_unfrozen`。普通旧工作流继续在修宪前策略内单调升级，
不会因为读取或普通 transition 被暗中增加作品展开图步骤；只有显式记录展开图时才开启
新治理，且不能降级。若当前迭代已有活动，新治理从下一轮开始；已经终止的历史保持不可变。
MCP 新建工作流时修订合同默认启用，`composition_governance` 默认 `true`，可为旧流程兼容显式传 `false`；
直接 Python API 继续以 `false` 为默认，避免旧调用暗中改变语义。测试模型裸能力时不接入 MCP。

## 受管渲染授权链

高层 `render_workflow_candidate` 不接受路径，也不接受 caller 构造的 authorization。
内部闭环为：

```text
当前 reviewing 修订
  → 发布唯一 candidate_pending 预留
  → 从预留生成精确 authorization
  → 渲染器再次确认预留仍为 current 且未消费
  → 同一 authorization 写入 render receipt 与 candidate manifest
  → 候选完整性、工程修订、父候选和工件 Hash 复验
  → workflow 记录候选锚点并消费预留
```

authorization 同时绑定 workflow、工程、预留修订、迭代、操作、authoring revision、
候选 work/id，以及父候选 work/id/manifest Hash。复制一份 shape 正确的 JSON 不是权限。

相同操作在断线后重试会复用并复验同一候选，不重复渲染或重置预算。若渲染失败，
状态保留在 `candidate_pending`，失败结果带当前快照；调用者可按新修订重试，或调用
`cancel_workflow_render`。旧预留在消费、停止、回滚或 current pointer 前进后不能重放。

## 候选的三个事实

`inspect_authoring_candidate` 分开报告：

- `workflow_authorized`：该 authorization 确实来自当前完整历史中的不可变预留；
- `workflow_recorded`：当前 workflow aggregate 中存在与 manifest Hash 完全一致的候选锚点；
- `workflow_accepted`：终止记录以四相复核后的 accept 精确选择了这个候选。

`workflow_managed` 只是兼容字段，仅在 `workflow_authorized=true` 时为真。一个候选可以
已授权但尚未记录，也可以已记录但尚未接受；三者不能互相冒充。普通原子 authoring
渲染三项都为假。audit 接入的既有候选保持 unmanaged，不能通过该 workflow accept。

## 决策、修订与回滚

`iterate` 允许 `accept`、`revise`、`preserve`、`stop`；`audit` 还可
`recommend_revision`。所有新决策都必须选择所采用的复核并逐条处置本轮非 hard-failure
证据；`revise` 还必须至少标出一个 `revision_target` 并填写
`expected_audible_change`，随后进入 `revision_pending`。Agent 随后
通过正常 authoring 工具读取、编辑并 CAS 保存完整 documents，再用
`record_workflow_authoring_revision` 绑定新修订。没有任何 workflow 调用会偷偷产生这份
修改。

最新治理还把这次 revise 冻结成一份**修订合同**。`revision_scope` 必须在动手前声明：
有限修订列出允许变化的文档，`allowed_document_paths` 的键必须与这些文档完全一致；
每份文档最多列出 1024 条精确 RFC 6901 叶子路径，每条路径最多 1024 个字符且 UTF-8
编码最多 1024 字节，路径不授予前缀或通配权限。score 音符不走数组路径，而是由
稳定 `event_ids` 和允许的音符字段精确限定；有限修订不允许重排，`bar_ranges` 要求
`end >= start`。范围校验覆盖合同 causal fence 之后直到绑定目标的每个持久化 save state；
中间一度越权，即使最终 documents 恢复，也会拒绝，不能“先重盖再回填”。整曲重构则必须先承认
扩大改动面、下游兼容重做和跑题风险，且 `allowed_document_paths` 为 `null`。
`withdrawal_condition` 同时写明什么证据出现时应撤回挑战者。绑定新 authoring 修订时，
机器只比较实际改动是否越过这份合同；越界会被拒绝，但“未越界”绝不等于“更好听”。

下一轮裁决必须用 `prior_revision_assessment` 结清上一份合同：
`promote_challenger` 才让挑战者成为后续修改基线；`retain_baseline` 与 `inconclusive` 都
保留合同冻结的完整基线且不冒充已经证明改好。若 workflow 到此停止，终态直接选择该
基线；若还要继续编辑，则先 rollback 回基线。assessment 必须引用本轮已经
记录并选用的 review / evidence / exception / derivation，并至少包含一个与冻结终审身份及
感知依据相符的当前复核。`promote_challenger` 必须已有挑战候选；若撤回条件在渲染前已成立，
可以用 `candidate_id=null` 的当前 `report_only` 复核支持 `retain_baseline` 或 `inconclusive`，
这不表示已听过挑战者。停止 workflow 不会删除合同基线，
未 promote 的挑战者也不会仅因“它是最新版”自动取代它。

受相因治理时，`revision_pending` 的 `next_action` 会先要求区分“只改谱”还是“需要改宪”。
只改谱才进入 `get_authoring_snapshot`；需要改宪则先预检、回显精确成本并提交账本；
提交前可以读取当前 score 以权衡代价，但不能编辑或保存替代 score。随后
`prerequisites` 明列“读取 → 只做有证据且不超出已确认范围的完整文档编辑 →
`save_authoring_project` → `record_workflow_authoring_revision`”；
`continuation` 保留 workflow ID 与预期 workflow 修订，因此 authoring CAS 保存不会丢失
返回工作流的位置。旧合同仍沿用直接改谱路径。

`rollback_creative_workflow` 选择较早迭代的已验证候选锚点，生成新迭代；它不移动
authoring current pointer、不覆盖旧修订，也不删除失败或未理解的候选。
回滚后继续修订时，内容从合同基线 revision 读取，但保存 CAS 的父修订必须使用
`authoring_causal_fence.anchor_revision`（仍是当前 authoring head）；这样既不把 pointer 倒退，
也不会把已撤回挑战者的内容当成新基线。
这项保证只覆盖**同一 workflow、同一 authoring project 链**。新建或关闭 workflow、跨项目
创作不会继承该基线；当前版本不引入全局单活、跨项目父版本树或新的 A/B 播放系统。

## 段落级推导：为何不得不如此

证据记录"哪里有问题"，例外记录"为何不得不偏离"；工作流增加第三种记录，
回答"谱面上在的东西为什么必须在"：

```text
record_workflow_derivation
```

推导是段落级的肯定性必然性主张，不是评分，也不阻断任何流程。它是稀缺论证，不是
逐小节配额；只应记录在会重写后续可能空间的节点，例如身份建立、形式转折、高潮
权限和结尾。普通延续、装饰或已经没有实质备选的地方，不需要为了填满预算制造推导。

- **锚点**：用非空 `event_ids` 和/或完整的 `start_bar`、`start_beat`、
  `end_bar`、`end_beat` 锚定当前 authoring 修订上的一段材料。小节/拍号范围是
  `[start_bar:start_beat, end_bar:end_beat)` 半开区间，终点不属于目标。
  `part_ids` 只用于过滤、收窄上述范围，不能单独构成锚点；与 `event_ids` 同用时，
  每个事件都必须属于所列声部。候选绑定的 `start_seconds` / `end_seconds` 若提供，
  只是补充的渲染时间窗，也不能替代事件或小节/拍号锚点。所有指涉在记录时对照
  锚定 score 校验，score 的规范化 Hash 嵌入记录，使主张与具体谱面版本绑定。
- **前提**：至少一条。四种类型：`declared_promise`（宪章字段）、
  `active_clause`（已激活条款）、`established_material`（作品自身已建立
  的材料，以 event_id 指涉）、`render_measurement`（绑定候选工件 Hash 的
  测量）。`established_material` 的每个事件起点必须严格早于目标起点；目标自身或
  未来材料不能倒过来证明当前决定。最强形态是作品内部的蕴涵：因为前文建立了
  什么，所以此处只能如此。
- **被排除备选**：至少一条，每条包含失败理由和非空 `premise_indexes`。
  `premise_indexes` 是去重的、从 0 开始的前提索引，必须落在本条推导的 `premises`
  内，使每个失败理由明确指回其依据。"为何不得不如此"是关于备选失败的断言；
  没有备选或不指回前提的"理由"只是偏好陈述。
- **条款与牺牲**：可列出推导所依据的激活条款和本推导承认牺牲的价值。

推导永不阻断、永不触发自动修改，也不替代耳朵的终审。经
`decide_workflow_iteration` 作出的 accept、revise、recommend、preserve 或 stop 决策都可以通过
`derivation_ids` 把所采用的推导纳入决策的持久主张；独立应急终止接口不选取子集，
但所有推导仍保留在
不可变 workflow 历史中，可由 `verify_creative_workflow_history` 复核。
推导预算 `max_derivations_per_iteration` 默认 8，可设为 0 整体关闭；它是防止论证
膨胀的安全上限，不是每轮必须完成的数量。

听审顺序不变：先听、后裁、再读推导。推导用来审查裁决是否站得住，不用来
在听之前说服耳朵。

这里的 provenance 仍只完成了一半：workflow 完成或停止后，推导会留在不可变历史中，
迭代决策也能以 `derivation_ids` 固定其采用的记录；但当前 workflow 受管的 Candidate v2
与独立 direct Score-v2 链的 Candidate v3 都是已封闭字节集，不会内嵌这份账本，
单独携带候选的消费者仍看不到它。后续应以独立的 **Candidate Provenance Envelope** /
portable bundle 绑定原候选 manifest Hash、终局 workflow 修订和所选推导，同时保持原
候选字节不变。在该外层合同实现前，不得在 accept 之后向候选目录或 render receipt
追加旁车文件；那会破坏已经发布的闭集完整性，而不是真正冻结 provenance。

## 宪章清偿：承诺账

证据处置清算的是问题账，宪章清偿清算的是承诺账。最新策略以
`charter_settlement_profile=affirmative-promise-ledger-v1` 标识，每个新决策都显式携带
`charter_settlement`，对冻结宪章中的每一项肯定性承诺逐条交代：

- 清偿目标由宪章机械枚举：`one_sentence_promise`、每一条
  `identity_kernel.invariants[i]`、`ending_contract`。
  `prohibited_shortcuts` 不是清偿目标——它们是负向约束，违反它们仍然必须
  走以宪章字段为目标的例外登记。
- 每个目标至多清偿一次，状态为 `kept`（如实兑现）、`transformed`
  （变形兑现）或 `refused`（拒绝兑现）。宪法 v0.2 的 C6.1.12 允许结尾完成、
  改写、悬置、消散、循环、拒答或突然停止；清偿不替审美裁决，只强制如实声明
  冻结承诺最终如何被处理。
- 每条清偿必须引用非空 `basis_ids`，且只能引用同一决策已选择的
  review、evidence、exception 或 derivation；`transformed` 必须引用推导，
  `refused` 必须引用例外或推导。可选 `event_ids` 在记录时及以后每次历史读取时都
  对照锚定修订的 score 复验；改写为不存在的事件不能靠重新封装历史逃过校验。
- **accept 要求清偿覆盖全部目标**；preserve/stop 允许部分清偿或不清偿，
  未清偿的承诺如实保持未清偿。历史 accept 没有清偿字段时继续按旧合同
  可读，不会被回填成“已清偿”。

机器只验完整性、指涉有效性与状态合法性，不验“兑现”在听觉上是否真实；
清偿是论证闭环，不是审美证明。

## 分支声明：整曲的可能世界

一个片段可以有两种写法：有人主张此处应抑扬顿挫，有人主张此处应激情上扬，
而两者各自成立，像平行宇宙，各有其不得不如此的理由。`record_workflow_fork`
为这种多解性提供容器：

- **一个分支永远是一首完整的曲子**，不是可替换的碎片。每个 branch 引用
  一个本 workflow 此前已记录的完整候选（work_id / candidate_id / manifest
  Hash 三元组），并写明该世界 embody 的立场（stance）与可选的当前迭代
  推导；当前迭代候选必须是 branches 之一。片段级替换只是渲染性能问题，不属于
  workflow 合同。
- **锚点**说明世界在哪里分岔：用 event_ids 和/或半开小节/拍范围锚定当前
  authoring 修订并嵌入其规范化 Hash。part_ids 只是过滤器，不能独立成锚；若与
  event_ids 或范围同时出现，事件必须属于所列声部并落在范围内。
- **`invariant_indexes`** 至少一条，指向宪章 identity_kernel.invariants 的
  序号，声明哪些身份不变量在所有分支中保持——这就是“它们仍是同一首曲子”
  的合同依据。
- fork 不阻断、不给分支排序、不替代听审。它落实宪法 v0.2 C7.1.02
  “分支须自立”与 C7.1.03“共源不求胜负”：未选中的世界不被丢弃，也不被
  降级成“失败版本”。

每轮迭代至多 8 条 fork。每次读取都会从 workflow / iteration / fork 正文重新计算 ID，
并重验 score 规范化 Hash、event / part / range 指涉及 branches 的已记录候选绑定；仅把
旧 ID 贴回改写正文不能重新封装成功。

当前 fork 是**稀疏的 whole-work alternative declaration**：只有确有多个完整候选需要
并存时才记录，不是每轮关卡，更不是 epoch/LCA lineage。它不声明分支祖先、共同祖先、
合并点或因果演化；这些需要以后独立的谱系合同。没有真实多解时直接裁决，避免为了
填日志制造分支。

## 权限

终审身份在创建时冻结。由 stdio MCP 创建的 workflow 永远使用
`final_authority=agent`；decision、rollback 和 stop 工具没有 authority 参数，而是核对
冻结值。MCP 不能把一次模型调用写成“创作者已批准”。

需要人类终审时，应由可信宿主入口创建 `final_authority=creator` 的核心 workflow，
或让 MCP workflow 以 `human_review_required` 停止。Agent 可以提供证据和候选，但身份
不能靠 caller 自述升级。

## 路径与恢复

所有高层 MCP 工具只接收 `project_key`、workflow ID、修订 Hash、候选 ID 和结构化
内容。服务端把工程映射到固定 authoring namespace，输出不含本机路径。受管 render
与 record 之间需要的候选绝对路径只在服务内部短暂使用。

语义错误返回稳定、无路径的 `error.code`。CAS 冲突或断线后的正确恢复顺序是：

```text
open_creative_workflow
  → 读取当前 workflow.revision、status 与 next_action
  → 重新判断原操作是否仍适用
  → 用当前 expected_revision 重试、取消或停止
```

不要盲重放旧 revision。需要证明完整父链时，显式调用历史验证工具；这是一项审计，
不是每次状态读取的隐性成本。

## 当前证据边界

v0.7 建立了状态、权限、证据、例外、预算、不可变候选、重试和审计的基础闭环，并用
真实最小渲染验证 transport 与工件绑定；`1.0.0` 继续补上内容 ID 重算、谱面指涉复验、
逐条主张处置、终局交叉绑定，以及当前作品内部的展开图、问题复核和有界修宪。它仍不能
替代实际听审，也不会把偏好案例库当作生成输入：那容易让模型过拟合、拼接或照抄。

- A/B 候选继续由渲染内核和调用者标签承担，不再复制一套偏好学习系统；
- 合奏问题在真实听审或社区反馈出现后，回到独奏、协作、配器或渲染证据中定位，不制造
  无法穷举的自动“合奏正确”结论；
- 后续优化优先加强当前作品自身材料之间的推导、全曲一致性与闭环，而不是喂入旧作品；
- 保留完整候选、未修订初稿与暂时无法解释的材料，让人耳决定比较关系，让仪表只陈述
  它真正测到的事实。
