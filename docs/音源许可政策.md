# 音源许可与署名政策

项目代码采用 Apache-2.0；输入作品、输出音乐与第三方音源继续受各自权利条件
约束。无论预期用途是否商业，都不能降低音源来源与许可门槛。是否接入也不得以
“同类项目普遍使用”“网上传播很多”或权利人不太可能追究来判断；项目需要能够
用固定上游、许可证原文和实际文件摘要正面证明自己的使用路径。
新接入的第三方录音默认只接受下列两类：

- `CC0-1.0`；
- 有明确作者、来源和署名要求的 `CC-BY-3.0` / `CC-BY-4.0`。

已有资源若采用其他公开许可，继续按原许可证和已冻结证据单独管理；新资源不因
“免费下载”、项目暂不收费或网页可直接访问，就推定获得了复制、修改或再分发权。
`CC-BY-NC`、来源不明、无许可证、从成品音乐提取以及许可证相互冲突的资源，默认
不进入新的候选乐器。确需例外时必须先单独审查，并与代码、公共音源目录和分发物
隔离。

外部音源清单使用三种受控状态：白名单内资源为 `approved`；白名单政策建立前已存在、
但只能按冻结证据和原许可证继续保留的资源为 `grandfathered`；无法确认预定音乐输出
是否合法、安装链不能对应到可信上游，或存在许可证冲突的资源为 `quarantined`。
后两类必须逐乐器登记在
[`音源许可例外.json`](音源许可例外.json)，其中 `quarantined` 不得进入可信乐器列表或
发布资源集合。例外登记只记录既有事实，不扩大原许可证授予的权利。

`local-compatibility-only` 是运行通道，不是把证据不足资源伪装成第四种许可
状态：这类 SoundFont 不登记为项目乐器，也不进入默认安装、公共 catalog /
capabilities、MCP、trusted 或协作层。用户只能通过明确文件路径在本机测试。
GeneralUser GS 因上游已披露部分样本来源无法完全确认，TimGM 因 GPL-2.0
没有明确的渲染音频输出例外，均按此边界保留；它们不会互相静默兜底，其渲染
结果也不作为天籁公开发布物。

若官方采样库本身由多种公开许可组成，但项目满足以下全部条件，可以作为既有
`grandfathered` 资源使用，而不要求天籁重新为官方发行包内的每个 WAV 建立一套
上游再分发权利链：

1. 安装器只从作者或项目官方指定的下载链取得固定版本完整发行包；
2. 归档大小、SHA-256、合并后的文件树摘要和许可证据均已冻结；
3. 音源只在用户本机原样解压，天籁不托管镜像、不抽取子集、不修改或重新打包；
4. 上游明确允许用该发行包制作并发布音乐，且所需许可/署名文件随本机安装保留。

这项规则只解决“能否按官方方式安装并用于渲染”，不授予天籁重新发布采样库的
权利。若以后需要镜像、裁剪、融合、格式转换或单独发布其中的 SFZ/WAV，必须回到
逐来源、逐派生链审查；证据不足时重新标为 `quarantined`。

这里的“发布资源集合”指由天籁携带或托管的原始/整理后采样、SFZ、可抽取音源包，
不包括安装器让用户从官方上游直接取得完整原包，也不等同于正常编曲渲染出的音乐
成品。若上游证据明确允许用音源制作音乐，项目可以发布普通音乐成品或将短试听用于
大众审核，但不得把干音、分轨、半音阶试音等作为独立采样素材包宣传或再打包。

第三方版权曲目的作品权与乐器音源许可分开管理。只有使用者确有相应权利时，
这类曲目才可用于其自行控制的本地评估；公开演示与大众审核只使用原创、获得
明确公开许可，或作品和具体谱面版本均可合法使用的材料。

每个新音源接入至少保留以下证据：

1. 官方项目页、持久 DOI 或作者发布页；
2. 固定提交、固定版本或带校验和的数据集文件；
3. 许可证原文及作者/演奏者/采样库名称；
4. 实际使用的 SFZ、采样集合和许可证据 SHA-256；
5. 对重映射、调音、降噪、切分或格式转换的明确说明；
6. 安装脚本只写入根目录 `音源/`，先在临时目录校验，再原子安装；已有目录不覆盖。

轻量源码发布包不携带实际音源、虚拟环境、渲染输出或下载缓存。如果以后单独分发
采样资源或基于它们生成的资源包，应随包保留相应署名、许可证链接、来源链接和
修改说明。该规则同时适用于非商用发布。

每次实际渲染会同时生成机器可读的 `许可与署名.json` 和简短人读
`许可与署名.txt`。单乐器 WAV 使用与 WAV 相邻的
`<文件名>.许可与署名.json/.txt`，合奏则放在成品目录根部。两份 sidecar 只收集
这一次确实参与渲染的乐器清单，不把 103 件全局许可表混入；JSON 还以 SHA-256
绑定本次合奏/分轨或单件 WAV。作者、上游、来源或许可字段没有写在乐器清单里时，
字段保持 `null` 并产生告警，绝不从文件名或常识补猜。对外发布时应随成品保留
sidecar，并继续核对其中每项上游许可证原文；自动生成的清单不能扩大上游授权。

对项目自研 DSP 不从乐器类型或名称猜测来源；只有清单同时满足
`provenance_kind=project_authored_dsp`、`implementation_license=Apache-2.0`、
`external_audio_assets=[]`、`audio_asset_license=not_applicable` 和
`license_status=approved` 五项结构化声明时，sidecar 才显示“自研 DSP /
无第三方采样”，并把上游音源条款标为不适用。五项中任何一项缺失或矛盾，仍按
普通来源不完整处理并保留告警。代码、输入作品和输出的完整边界见
[`OUTPUT_RIGHTS.md`](../OUTPUT_RIGHTS.md)。

许可证证据是最低准入条件，不代表音质合格。资源仍须通过音域覆盖、端到端音准、
力度/轮转、起音与尾音、爆音/削波、确定性和人工盲听等独立质量门槛。
